# MLS Assist 3.0.122 final candidate audit

Candidate only. Supersedes 3.0.121; no browser extension was installed/reloaded,
no live Athena access or clinical write occurred, and nothing was published.

## Reproduced defect and narrow repair

The 3.0.121 AX reader accepted a request for encounter 101 while the frame still
showed encounter 100. Its navigation response proves only that navigation was
requested; the subsequent patient check can legitimately succeed on both
encounters of the same patient. The body reader had no exact encounter binding.
The new executable regression failed on those original bytes.

The same original reader interpreted the first date anywhere in the page as
the encounter date. An executed synthetic baseline with DOB 01/02/1960 before
an encounter date of 09/10/2026 returned 01/02/1960. In a scoped read this could
incorrectly exclude the required day's clinical note as an older encounter.

3.0.122 requires the exact same-origin encounter route before and after body
capture. Unbound, foreign, stale and changing routes refuse. The worker sends
the frozen route, verifies it on the body result, and gives an unsettled route
a bounded 5.2-second retry window under the original absolute read deadline.
The patient identity gate remains before capture and is run again after
capture, before any body is kept or any date exclusion is accepted. A patient
conflict, wrong encounter body, exhausted settling window or missing frame
remains counted in the incomplete receipt and existing retry path.

Only explicit encounter/visit/service-date labels now supply the encounter
date; a DOB or unlabeled page date cannot prove an out-of-scope exclusion.
Missing or conflicting labeled dates remain unknown. This intentionally does
not invent an Athena DOM header shape: supported live date labels must still
be checked during acceptance. The appointment's scheduling note is a separate
field and retains the complete, exact-appointment capture from 3.0.121.

The surgical source replacement script verifies that reversing its changes
restores every original byte, including the mixed line endings. The native
ActionV2 write driver and all other extension package files except the source
manifest are unchanged from 3.0.121.

## Still requires authorized live acceptance

1. Verify the installed version and core digest after an authorized reload,
   preserving exactly one signed-in Athena tab and the original enabled copy.
2. For the reported failed schedule rows, reconcile each requested appointment
   ID/date with the actual row and the closed opener reason. Generic open
   failure is not evidence that a patient is absent from the schedule.
3. With Full Notes ON, compare exact expected encounter IDs and body text with
   the source and persisted results. Every missing, failed or unattempted
   encounter must be accounted for. Exercise delayed encounter navigation and
   verify the new binding check sees the actual rendered AX route/date labels.
4. Separately prove the pulled day's own note and the next appointment's
   available scheduling note survive persistence and enter the required OP-note
   context. Future clinical text that does not yet exist must never stand in
   for, or excuse loss of, an available future appointment scheduling note.
5. Reconcile actual running jobs and every row outcome with Activity during
   retries, tab occlusion, stale frames, SPA navigation and reload/resume. No
   global complete claim is allowed while any required row remains unresolved.
6. Any live draft write/save acceptance requires a separately authorized exact
   dummy chart, action and text. No real-patient or final clinical action is
   authorized by this audit.

Passing local checks is not a claim of perfect live reading, OP-note context,
persisted writes, or commercial release acceptance.
