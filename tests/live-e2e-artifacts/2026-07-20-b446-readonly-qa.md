## Defects found (each root-caused live, fixed in b447, regression-tested)

1. **THE history clobber — `clinical-field-save-unproven` on 11–14 of 16
   patients, reproduced on 3 consecutive live day pulls.**
   Instrumented taps proved: `_savePatientChart` stamps `athenaProfileCoverage`
   and upserts the verified clone (tap: `hasCov:true`), then 3–6 ms later the
   post-save ingest chain (`ingestChart→addVisit→_upsert`, reached from both the
   F13a belt-and-braces at mls-connect:20836 and the visitwire post-hook)
   re-upserts a patient object materialized BEFORE the save — erasing
   coverage/snapshot/summary-block/import-stamp. The pull's own read-back gate
   then refuses. Survivors per pull were random (2–3); retries converged slowly
   (14→12; persisted coverage rows grew 3→9 over five passes).
   Ruled out live: cross-tab writers (second app tab logged ZERO savePatients
   during a full retry), account-namespace flips, wipe-guard, dedup redirect,
   visit-level hydrate.
   **Fix:** base `upsertPatient` (ScribeFlow + staging) carries the four
   Athena-owned proof fields forward when a same-id caller merely lacks them;
   fresh values still win; purge untouched.
   Test: `tests/upsert-athena-proof-carryforward.test.js`.

2. **Sanitizer ingest wrapper dropped `opts`** (mls-connect ~11022): every
   sanitized `ingestChart` lost `identityVerified`/`identityBinding`, filing
   pulled visits as UNVERIFIED — breaking provenance honesty downstream.
   **Fix:** forward the 4th argument. Pinned in the same test.

3. **First-click day pull failed after an app reload** (`nav-failed`, "athena
   week strip shows no selected day") with Athena parked on the dashboard; the
   identical second click succeeded ~4 min later; a `probe:true` goto showed
   `controlVisible:true`. One 2.5 s settle was too short for the dashboard→Day
   render. **Fix:** si-1.7.14 escalating settles 2.5 s / 5 s / 8 s.
   Test: updated `tests/ext-update-hint-contract.test.js`.
   **Live re-test on b447: the first click after reload navigated successfully.**

4. **Missing-marker honesty gap** (the open provenance-ambiguity question):
   a pulled visit row with NO text at all and no markers displayed the
   "partial — a copied excerpt was pulled" chip, claiming content that does not
   exist. **Fix:** such rows now read "index only" with the re-pull remedy.
   Test: `tests/visit-history-provenance-chip.test.js` case 2b.
   (b442's chip already covered the unflagged-excerpt class as "partial" and
   verified bodies/clinician rows as unmarked.)
