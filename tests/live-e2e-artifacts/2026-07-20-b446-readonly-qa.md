   patients, reproduced on 3 consecutive live day pulls.**
   Instrumented taps proved: `_savePatientChart` stamps `athenaProfileCoverage`

   post-save ingest chain (`ingestChart→addVisit→_upsert`, reached from both the

   fresh values still win; purge untouched.

## /api/versions/report error: RESOLVED with backend-log proof

Root cause chain: the worker's fire-and-forget report is a cross-origin fetch;
the backend allowlists web origins + one canonical extension id, and the
RUNNING 2.9.43 manifest lacked the backend host permission, so every report
died on CORS (silently — the .catch swallowed it; the worker console showed
the error). Fix (minimum permission): ONE narrow host permission
`https://scrivara-backend.onrender.com/*` in the 3.0.0 manifest makes the
worker fetch CORS-exempt. No backend change, no origin widening.
**Proof: Render application logs show
`[versions] client report: component=mls-assist version=3.0.0` after load.**
Regression pinned in `tests/extension-package.test.js` (the host permission
must stay; exactly one onrender origin; background must post to the endpoint).
Bonus fix: the webapp's own report sent `build=unknown` (IIFE-scoped
MLS_APP_BUILD) — now falls back to `window.__MLS_AV`.
