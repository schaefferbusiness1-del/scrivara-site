## Confirmed defect and repair

The ax fallback already knew when its harvest was smaller than the classic
encounter index. With six known rows and four harvested/read bodies, it returned
`complete:false`, `expected:4`, `parsed:4`, and `indexRowsKnown:6`. The shared
terminal hop ignored that refusal and recomputed completion from 4 == 4, changing
the result to `complete:true`.

`ax-history-census-terminal-runtime.test.js` executes the actual fallback closure
and actual terminal block together. It failed on 3.0.117 at the assertion that a
four-of-six history must remain incomplete. The healthy four-of-four control
passed on those same bytes.

The candidate now preserves the larger known full-history population, returns
`ok:false` with `visit-bodies-incomplete` for a partial fallback, and preserves
the prior completeness decision at the final hop. The same example reports
expected 6, parsed 4, attempted 4, not attempted 2, and incomplete. A deadline
reports the number of navigations actually attempted, rather than the planned
cap. This allows the existing retry path to see and retry the partial read.

The new regression also covers caps, deadlines, failed navigation, an identity
refusal, independent completeness refusals, and legitimate zero-body outcomes.
It checks returned synthetic encounter IDs against the operations actually run.
It does not claim that a live ax harvest necessarily contains the whole chart;
that remains a live index/ID comparison requirement.

`scripts/splice-30118.js` makes only unique literal replacements and verifies
their inverse restores every original byte, preserving the mixed line endings
in `background.js`. The native ActionV2 write-driver block is identical to the
3.0.117 staged copy. No site source file was edited.
