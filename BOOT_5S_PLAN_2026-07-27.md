# The 5-second bar (owner hard requirement, 2026-07-27)

"Loading in should take less than 5 seconds" — general, not just post-eviction.

## Measured today (live, b728/b729 era)

- Visible-tab boot (owner-opened fresh tab): first paint 304ms, DCL 571ms,
  load 642ms — the PAGE is fast. But scripts kept arriving until
  **118,058ms** (212 scripts, 211 served instantly by the SW).
- Hidden-tab boot: DCL 1,725ms; script tail 55s.
- Network is NOT the cost (SW serves everything, transferSize 0). The cost is
  (a) serial main-thread parse/execute of the ~233-eager `s.async=false`
  chain, (b) idle-ladder assembly popping surfaces in for minutes, (c) the
  sign-in path's hydration burst (1,500-patient store) — the recorded prior:
  boot TBT lives in the PATIENTS SCREEN, one forced layout = 18ms.
- There is NO time-to-usable instrumentation: zero performance.mark calls;
  the readiness system (br-1.0.0) does not stamp times.

## Plan (in order; each gated + live-measured)

1. **Instrument first**: performance.mark at the moments that matter —
   boot-gate clear, dock interactive, day strip rendered, patient store
   hydrated, visit surface interactive, LAST eager module done. One
   `window.__mlsBootTimeline` reader. Measure a real signed-in visible boot.
2. **Targeted deferral** from the measurements: anything >5s that the doctor
   needs is either moved earlier or made not-needed (the surfaces must be
   COMPLETE at paint, not popping in).
3. **Collapse the eager chain if still over bar**: build-step concatenation
   of the eager set into one bundle (big change: bump machinery, publication
   inventory, boot-script-budget, SW precache — full pin sweep). Only if 1+2
   don't reach 5s.

Bar: sign-in → working workspace < 5,000ms, proven on the live signed-in
visible tab, twice consecutively. Task #28.
